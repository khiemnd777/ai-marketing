# R2 lifecycle and recovery

- Keep the bucket private; block anonymous access and use short-lived server-created presigned URLs only.
- Enable object versioning. Retain non-current versions for at least 35 days so they outlive daily database backups, and abort incomplete multipart uploads after 7 days.
- Use scoped keys containing workspace/campaign or asset identity generated by the server. Reject client-provided traversal components and verify SHA-256 after every upload/download used by AI or rendering.
- Temporary Seedance downloads are copied immediately to the durable bucket. Renderer inputs are downloaded to a per-job directory, checksum-verified, and removed when the job exits.
- Transition archive-eligible non-current versions only if retrieval latency meets the four-hour RTO. Do not expire selected renders, active publishing/Ads creative, consent evidence, or objects under legal hold.
- Alert on transfer errors and unexpected storage growth. Review PostgreSQL `media_asset_versions.file_size_bytes` against provider bucket inventory monthly; investigate orphans in both directions before deleting anything.

Lifecycle changes require a dry-run inventory, two-person review, and a restore sample that pairs an older PostgreSQL backup with matching object versions.
